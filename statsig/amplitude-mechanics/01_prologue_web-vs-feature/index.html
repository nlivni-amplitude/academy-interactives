Two ways into an experiment on the same platform, same stats. The choice comes down to one question about the change you're making.

Can you describe your change by pointing at a webpage?

Web experiment

A visual editor, URL targeting, and redirect tests, run on the site through a browser snippet. Built for marketers to launch without a release cycle. A focused slice of the toolkit, no sticky bucketing.

Feature experiment

SDK and flag based, code-level variants on web, mobile, and backend. Deployments, sticky bucketing, flag dependencies. Needs engineering, buys you unlimited scope.
Explained in non-technical terms
Web experiment is a sticker kit: a marketer opens the visual editor, points at the live site, swaps a headline, and it's live by lunch. Feature experiment is a workshop: engineers wire variants into the actual code behind flags, on any surface including the backend. Stickers change the surface, the workshop rebuilds the machine. If it needs a pull request, it's the workshop.

At AmpliStore, testing "Glow up your routine" against "Skincare that works" on the homepage is a web experiment, live the same morning. Testing a new shade-finder quiz flow in the iOS app plus the checkout API behind it is a feature experiment, because there's no sticker for a quiz engine.
