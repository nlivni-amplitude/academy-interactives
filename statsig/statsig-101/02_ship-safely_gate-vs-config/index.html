Both are ways to change what your app does without a code deploy. The difference is the kind of question each one answers: a gate answers whether a user sees something, a dynamic config answers how that something behaves.

Explained in non-technical terms
A gate is the light switch: the light is on or off. A dynamic config is the dimmer and the color dial: the light is already on, and you're setting how bright it is and what shade. One decides whether the thing exists for a user, the other decides what values it runs with.

You reach for a gate when the question is on or off, a rollout, a kill switch. You reach for a config when the question is what values the feature should use, and you want to change button text, a threshold, or a weight without shipping code. Flipping the gate off makes the checkout disappear entirely; changing the config only changes how the checkout that's already there behaves.
