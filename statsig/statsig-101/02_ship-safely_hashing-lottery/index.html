You set a gate to 30% and one of your own test accounts doesn't get it. Nothing's broken. Every user got a number the moment they were first evaluated, and that number never changes.

8 users, gate set to 30%. Each one gets a fixed number from 0-99 the first time the gate checks them. Under 30 passes.
Run it once to assign numbers.
It's less a coin flip and more a locker number stamped on an ID card. The same person always opens the same locker, but nobody hands you a form to pick which locker you get. If a specific account needs in, an override skips the number entirely, it doesn't reassign it.

Re-running just re-checked the same locker numbers against the same threshold. That's why two evaluations back to back never disagree, and why "it worked yesterday, why not today" almost always means the rollout percentage changed, not that the math got flaky.
