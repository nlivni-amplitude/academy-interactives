A gate's been sitting at 100% for three months, so you archive it to clean up. The feature vanishes for everyone that afternoon. Stepping through what archiving actually changes shows why.

Step 1 of 4. The gate is Launched at 100%, so every shopper gets 1-click checkout.
The gate is a sticky note on the fridge that says "dessert is allowed," and the app checks the fridge every morning. Archiving throws the note away, and code that finds no note assumes the answer is no. If the checkGate() call is still in the app when the note disappears, dessert vanishes for everyone at once.

The order that avoids it: remove the check from the code, deploy, then archive. Two related safe-ops habits sit alongside this one. Saving an override touches production users, so it needs launch permission, not just edit access. And when you want proof the feature caused a metric to move rather than a signal that it might have, graduating the gate to an experiment keeps the targeting and adds the randomization that makes the result causal.
